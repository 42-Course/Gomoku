1//! # Gomoku engine
2//!
3//! A Gomoku (Five-in-a-Row, with captures and the no-double-three rule)
4//! engine: rules, search, and heuristic evaluation. Pure library — no
5//! binary, no I/O, no threads.
6//!
7//! Consumed by:
8//!
9//! - native callers via `[dependencies] engine`,
10//! - the browser visualizer through the `engine-wasm` crate, which wraps
11//!   this library in `wasm-bindgen` glue.
12//!
13//! ## Module map
14//!
15//! | Module           | Responsibility                                           |
16//! | ---------------- | -------------------------------------------------------- |
17//! | [`constants`]    | Board geometry constants (size as `usize` and `isize`).  |
18//! | [`board`]        | Bit-packed storage + line-walking primitives.            |
19//! | [`patterns`]     | Pure bit-twiddling pattern detection on packed lines.    |
20//! | [`game`]         | Rules: turns, captures, win, draw, double-three.         |
21//! | [`ai`]           | Negamax + alpha-beta with a heuristic evaluator.         |
22//! | [`transpose`]    | Fixed-size transposition table keyed by Zobrist hash.    |
23//! | [`zobrist`]      | Zobrist hash tables for incremental position hashing.    |
24//!
25//! ## Bitmap-driven design
26//!
27//! Stones live in two per-player [`board::BitBoard`]s. To recognize patterns
28//! ("five in a row", "open four", "free three", …), the board is sliced into
29//! lines (rows, columns, diagonals, anti-diagonals); each line is packed
30//! into two `u32` masks (`me`, `opp`); and recognition is plain shift+mask.
31//!
32//! Off-the-board cells sit at zero in *both* masks, which makes them act as
33//! walls — patterns that need an empty endpoint cannot match against an
34//! edge, so edge handling falls out for free. See [`patterns`] for the full
35//! treatment, and `engine/REFACTOR.md` for the historical context.
36//!
37//! ## Search
38//!
39//! [`ai::search`] runs negamax with alpha-beta pruning and a transposition
40//! table keyed by the incrementally maintained Zobrist hash. The evaluator
41//! ([`ai::evaluate`]) scores positions from the side-to-move's perspective
42//! using the pattern tallies above.
43
